# دستیار خرید حضوری ترب (پیش‌نویس README)

> چالش ترب · هکاتون Agentic AI استارکوچ
> یک دستیار هوش مصنوعی فارسی و راست‌به‌چپ برای **خرید حضوری در تهران** که روی دیتاست ترب ساخته شده است.

## ۱. مسئله
ترب به کاربر می‌گوید یک کالا کجا و با چه قیمتی هست. ولی خرید حضوری سؤال‌های سخت‌تری دارد:
- **الان** کدام مغازه باز است و کی می‌رسم؟ اگر مغازه‌های نزدیک بسته باشند، آیا رفتن تا مغازهٔ دورتری که باز است می‌ارزد؟
- مغازه داخل کدام پاساژ است، طبقهٔ چندم و کدام واحد؟
- برای یک پروژه (مثلاً برق‌کشی یک آپارتمان) چه چیزهایی لازم دارم و چطور همه را از مغازه‌هایی بخرم که نزدیک هم هستند؟
- این لباس روی من یا این مبل در خانهٔ من چطور است؟

**سناریوی نمونه:** ساعت ۲۳:۳۰ کاربر شارژر گوشی لازم دارد. مغازه‌های نزدیک بسته‌اند، یک مغازهٔ دورتر باز است، و در بورس موبایل نزدیک شاید مغازه‌هایی باز باشند که در ترب ثبت نشده‌اند. دستیار هر دو گزینه را با نقشهٔ کوچک و مسیریابی نشان می‌دهد و صادقانه می‌گوید کدام قطعی است و کدام فقط احتمال.

## ۲. قابلیت‌ها
وضعیت هر قابلیت با خواندن کد فعلی (۱ آبان ۱۴۰۵، حدود ساعت ۲۰:۱۵ به وقت تهران) بررسی شده است. هر جا نوشته شده «در حال تکمیل» یعنی آن بخش هنوز کامل در رابط کاربری دیده نمی‌شود.

| قابلیت | وضعیت | کجا در کد |
|---|---|---|
| **چت مشاور V3+**: یک عامل با ابزارهای دیتابیس (`find_products`، `sql`، `text_search`، `product_knowledge`، `bazaar_hubs`، `start_project`). رفتارش مشاوره‌ای است: حداکثر ۳ سؤال تکمیلی، حافظهٔ جلسه و پیشنهاد سؤال بعدی. مشخصهٔ فنی که در دیتابیس نیست را به‌صورت «طبق مشخصات سازنده» می‌گوید، ولی قیمت، مغازه و موجودی را **هرگز** از دانش عمومی نمی‌گوید. کارت‌ها یک بار و پس از بررسی نهایی فرستاده می‌شوند و با متن نهایی هم‌خوان‌اند | ✅ | `eval/agent_v3plus.py`، `v3plus_prompt.txt`، `playground_app.py` (`/api/send`، `/api/send_stream`)، `src/Chat.tsx` |
| **حالت شبانه/فوری** («الان کجا بازه؟»): وضعیت باز/بسته از ساعت کاری ثبت‌شده به وقت تهران، نزدیک‌ترین مغازهٔ **باز** (حتی اگر دورتر باشد)، تعداد مغازه‌های نزدیک‌ترِ بسته، بورس نزدیک به‌عنوان «احتمال»، و نقشهٔ کوچک MapLibre با مسیریابی نشان و گوگل‌مپ. برای تست: `?now=23:30&day=fri` | ✅ فاصله به‌صورت کلامی و «الان باز تا …» نمایش داده می‌شود. نمایش **زمان رسیدن** در خود بلوک شبانه: «در حال تکمیل» | `eval/playground_latenight.py`، `src/LateNight.tsx`، `src/MiniMap.tsx` |

| **لیست‌های ذخیره‌شده** (سبد مجازی): محصول به همراه مغازه، آدرس، قیمتی که هنگام ذخیره ثبت شده، و امکان به‌روزرسانی از دیتابیس | ✅ | `eval/playground_lists.py`، `src/Lists.tsx` |
| **صفحهٔ محصول**: همهٔ پیشنهادهای فروشندگان از دیتابیس با برچسب «قدیمی» (بیش از ۳۰ روز) و «مشکوک» (کمتر از ۴۰٪ میانه)، مشخصات و محصولات مرتبط بر اساس embedding. بخش «دربارهٔ این محصول» یک خلاصهٔ ۳ تا ۵ جمله‌ای است که با جست‌وجوی وب BoxAPI و ذکر منبع ساخته و کش می‌شود | ✅ | `eval/playground_drill.py`، `playground_about.py`، `src/Product.tsx` |
| **پرو مجازی** با AvalAI و مدل `gemini-2.5-flash-image`، روی عکس خود کاربر: برای پوشاک، کفش و اکسسوری روی عکس شخص، و برای مبلمان و دکوراسیون داخل عکس اتاق. عکس کاربر روی دیسک ذخیره نمی‌شود | ✅ | `eval/playground_tryon.py`، `src/tryon/` |
| **شیت مغازه**: آدرس، ساعت کاری هفتگی، باز/بسته، روش‌های پرداخت و شماره به‌صورت متن با یادداشت «شمارهٔ نمایشی». گزینهٔ «بسته بود؟ جایگزین بده» (نزدیک‌ترین مغازه‌های باز با همان محصول). «کجای پاساژه؟» (طبقه و واحد از آدرس، به‌علاوهٔ جست‌وجوی وب استناددار). مسیریابی با نشان و گوگل‌مپ | ✅ | `eval/playground_mall.py`، `src/Shop.tsx` |
| **راهنمای داخل پاساژ به سبک استوری اینستاگرام**: مراحل رسیدن ← طبقه ← واحد ← مغازه. مرحله‌ای که داده‌اش در آدرس نیست حذف می‌شود. آسانسور و پله‌برقی فقط با منبع وب استناددار گفته می‌شوند | ✅ | `eval/playground_mallguide.py`، `src/mallguide/` |

| **«ترب برام زنگ بزنه»** | ✅ فقط نمونهٔ رابط کاربری (mock): هیچ تماسی گرفته نمی‌شود و درخواستی به سرور نمی‌رود | `src/Shop.tsx` (`FollowSheet`) |

## ۳. معماری
```
React 18 + Vite + TypeScript (RTL، وزیرمتن)  ──same-origin──►  FastAPI (uvicorn، playground_app.py)
   │  MapLibre GL + OpenFreeMap (positron) برای نقشهٔ کوچک            ├─ عامل V3+ (agent_v3plus.py) ──► BoxAPI · gpt-6-luna (tool calling)
   │  Leaflet/OSM برای تب نقشهٔ فعلی                                   ├─ «دربارهٔ محصول»، «کجای پاساژه؟»، راهنمای پاساژ ──► BoxAPI web_search (با استناد)
   │                                                                   ├─ پرو مجازی ──► AvalAI · gemini-2.5-flash-image
   │                                                                   ├─ ماژول‌های بدون LLM: شبانه، نقشه، خانه، لیست‌ها، drill-down، بورس‌ها
   │                                                                   └─ SQLite فقط‌خواندنی: torob.sqlite (+ FTS5، embeddingهای ذخیره‌شده) · user_lists.sqlite
```
- **بک‌اند:** FastAPI. هر مسیر با توکن محافظت می‌شود و سقف هزینهٔ جلسه دارد (`PLAYGROUND_SPEND_CAP`؛ وقتی پر شود سرور پاسخ HTTP 402 می‌دهد). بیشتر endpointها هیچ فراخوانی LLM ندارند. فیلد `llm_calls` در هر پاسخ این را نشان می‌دهد.
- **عامل:** حلقهٔ tool-calling روی دیتابیس فقط‌خواندنی. مدل در متن فقط شناسه می‌نویسد (`[[offer:…]]`، `[[product:…]]`) و سرور قیمت و فاصلهٔ کلامی را از دیتابیس جایگزین می‌کند. پس از پاسخ، **Claim Check** ادعاهای «ارزان‌ترین»، «ارزان‌تر» و «به‌روزتر» را با یک کوئری SQL مرجع مقایسه می‌کند. اگر تخطی پیدا شود، یک بار پاسخ دوباره تولید می‌شود. ادعایی که باز هم رد شود حذف می‌شود و موردی که از قلم افتاده به‌صورت قطعی اضافه می‌شود.
- **فرانت‌اند:** React/Vite با `base: '/app/'`. خروجی build از مسیر `/app/?token=…` و از همان سرور FastAPI سرو می‌شود.

## ۴. اجرای محلی
> هیچ کلید یا توکنی در مخزن یا این سند نیست. مقدارها را خودتان در متغیرهای محیطی بگذارید.

**پیش‌نیازها:** Python 3.10 یا بالاتر، Node.js 18 یا بالاتر، و فایل `torob.sqlite` در `eval/` (از دیتاست ترب با `build_eval_db.py` ساخته می‌شود).

```bash
# ۱) بک‌اند
cd torob/eval
python -m venv /workspace/.venv && source /workspace/.venv/bin/activate
pip install fastapi uvicorn openai numpy

export BOXAPI_API_KEY=...        # چت، جست‌وجوی وب، embedding (BoxAPI)
export AVALAI_API_KEY=...        # پرو مجازی (اختیاری؛ می‌توان در فایل محلی .env_avalai گذاشت، که restart_playground.sh آن را می‌خواند)
export PLAYGROUND_TOKEN=<یک رشتهٔ تصادفی>
export PLAYGROUND_SPEND_CAP=0.50 # سقف هزینهٔ جلسه به دلار
uvicorn playground_app:app --host 127.0.0.1 --port 8765

# ۲) فرانت‌اند
cd torob-app
npm install
npm run build                     # tsc --noEmit && vite build  → dist/
# محتوای dist/ را در torob/eval/playground_app_dist/ کپی کنید (سرور /app را از آن‌جا سرو می‌کند)
# برای توسعه: npm run dev  (Vite روی 0.0.0.0؛ API هم‌مبدأ است، پس برای فراخوانی‌ها سرور FastAPI لازم است)

# ۳) باز کردن
#   http://127.0.0.1:8765/app/?token=<PLAYGROUND_TOKEN>
#   تست حالت شبانه:  http://127.0.0.1:8765/app/?token=<PLAYGROUND_TOKEN>&now=23:30&day=fri
```
اسکریپت `eval/restart_playground.sh` همین فرمان uvicorn را با متغیرهای AvalAI دوباره اجرا می‌کند. قبل از انتشار عمومی، توکنی را که مستقیم داخل این اسکریپت نوشته شده حذف کنید و آن را از متغیر محیطی بخوانید.

## ۵. قوانین ضدتوهم (غیرقابل‌مذاکره)
1. **قیمت، مغازه یا موجودی ساختگی نداریم.** همهٔ قیمت‌ها، مغازه‌ها و پیشنهادها از `torob.sqlite` می‌آیند و با `shop_id` و `offer_id` به هم وصل‌اند. مدل هیچ‌وقت عدد قیمت را خودش تایپ نمی‌کند. «پیشنهاد ثبت‌شده» یعنی موجودی تضمین‌شده نیست.
2. **شماره‌تلفن‌های دیتاست نمایشی و غیرواقعی‌اند.** شماره فقط به‌صورت متن و همراه با یادداشت نمایش داده می‌شود، لینک `tel:` ندارد و **هیچ تماس واقعی** گرفته نمی‌شود. «ترب برام زنگ بزنه» فقط نمونهٔ رابط کاربری است.
3. **هر داده‌ای که نداریم «نامشخص» است:** قیمت، ساعت کاری، طبقه و واحد. مرحله‌ای از راهنمای پاساژ که داده ندارد حذف می‌شود.
4. **فاصله‌ها فقط با کلمه گفته می‌شوند**، مثل «همین نزدیکی» یا «کمی دورتر»، و هیچ‌وقت به‌صورت کیلومتر اعشاری. زمان سفر تقریبی است و به شکل «حدوداً N دقیقه» نمایش داده می‌شود.
5. دانش عمومی فقط برای مشخصه‌های فنی ناموجود در دیتابیس استفاده می‌شود و با «طبق مشخصات سازنده» مشخص می‌شود. ادعاهای منسوب به دیتابیس با محتوای خود دیتابیس چک می‌شوند. هر واقعیتی که از وب می‌آید (درباره محصول یا پاساژ) باید منبع استناددار داشته باشد، وگرنه حذف می‌شود.
6. وضعیت باز/بسته بر اساس ساعت کاری ثبت‌شده است و تعطیلات رسمی در آن لحاظ نشده. بورس‌هایی که مغازه‌هایشان در ترب نیست همیشه «احتمال» معرفی می‌شوند.

## ۶. استفاده از دیتاست ترب
آمار زیر مستقیماً از `torob.sqlite` با پایتون محاسبه شده است (دیتابیس در ۳۰ مهر ۱۴۰۵ ساعت ۱۴:۵۳ به وقت تهران ساخته شده).

| داده | تعداد |
|---|---|
| محصولات | **۲۲۵٬۹۰۳** (۲۲۴٬۶۸۴ با تصویر؛ ۱۴۴٬۵۹۹ با مشخصات فنی) |
| ردیف‌های مشخصات فنی (`product_specs`) | ۱٬۲۲۷٬۵۱۱ |
| دسته‌بندی‌ها | **۳٬۴۲۸** (برای هر دسته یک «کارت دسته» با برندهای برتر و بازهٔ قیمت p10 تا p90) |
| برندها | ۲٬۲۴۹ |
| پیشنهادهای فروش (`offers`) | **۳۳۱٬۵۰۶**: ۳۱۴٬۶۳۴ با قیمت معتبر، ۱۵٬۰۸۳ بدون قیمت، و ۱٬۷۸۹ با قیمت خارج از بازه (کمتر از ۱٬۰۰۰ یا بیشتر از ۱۰۰ میلیارد تومان) که NULL شده‌اند |
| فروشگاه‌ها | **۶٬۴۷۶** (همه با مختصات جغرافیایی؛ ۳٬۷۹۲ با پیشنهاد فعال؛ ۳۰ برچسب محله) |
| ساعت کاری (`shop_hours`) | ۵۸٬۷۸۶ ردیف برای ۴٬۴۷۳ فروشگاه |
| دسته‌بندی‌های فروشگاه | ۶۴٬۶۵۹ |
| روش‌های پرداخت و اقساط | ۳۸۵ ردیف برای ۲۶۶ فروشگاه |
| فروشگاه‌های با ارسال سریع | ۱٬۱۶۸ |
| بازهٔ تاریخ آخرین تغییر قیمت | ۱۳ آذر ۱۳۹۹ تا ۲۱ مهر ۱۴۰۵ |
| embedding محصولات (ذخیره‌شده) | ۲۲۵٬۹۰۳ بردار ۲۵۶ بعدی |
| بورس‌های تهران (`bazaars.json`، ساخته‌شده از دیتابیس) | ۲۴ قطب در ۱۰ گروه کالایی |

**نحوهٔ استفاده:**
- **جست‌وجو:** FTS5 روی عنوان، برند، مدل و دسته، به‌علاوهٔ embeddingها برای پیدا کردن محصولات مرتبط و هم‌خانواده. نگاشت متن محاوره‌ای به دسته از طریق کارت دسته‌ها انجام می‌شود.
- **قیمت:** فقط از `offers`. پیشنهاد «قدیمی» یعنی بیش از ۳۰ روز از آخرین تغییرش گذشته. «مشکوک» یعنی کمتر از ۴۰٪ میانهٔ قیمت محصول است (حداقل ۳ پیشنهاد قیمت‌دار لازم است؛ اگر کمتر باشد، میانهٔ خانوادهٔ مدل ملاک است). ارزان‌ترین پیشنهاد به‌روز را سرور محاسبه می‌کند.
- **مکان:** `lat/lon` فروشگاه‌ها برای فاصله، نقشه و مسیر استفاده می‌شود و آدرس برای پاساژ، طبقه و واحد. `location_label` برای محله است.
- **زمان:** `shop_hours` برای «الان باز است؟»، «تا برسی بازه» و «جایگزین باز» استفاده می‌شود.
- **بورس‌ها:** تمرکز فروشگاه‌ها و پیشنهادهای هر گروه کالایی در دیتابیس، قطب‌هایی مثل بورس موبایل و برق را می‌سازد. این قطب‌ها در حالت شبانه، خرید جامع و «اینجا چی داره؟» استفاده می‌شوند.
- **محدودیت‌ها:** شماره‌تلفن‌ها نمایشی‌اند. موجودی لحظه‌ای در دیتاست وجود ندارد. ساعت کاری فقط برای بخشی از فروشگاه‌ها ثبت شده و هر جا نباشد «نامشخص» نمایش داده می‌شود.
